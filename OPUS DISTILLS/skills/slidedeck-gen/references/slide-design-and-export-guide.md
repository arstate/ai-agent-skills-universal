# Slide Design & High-Fidelity Export Engineering Guide

This guide establishes the technical and aesthetic standards for publication-grade 16:9 presentation decks generated by `slidedeck-gen`.

---

## 1. Mathematical Geometry of the 16:9 Canvas

A modern presentation is designed for widescreen monitors (16:9 aspect ratio). 

- **Internal Base Coordinates:** `1920px` width by `1080px` height.
- **Aspect Ratio:** `16 / 9` (1.7777... ratio).
- **Safe Margins:**
  - Horizontal padding: `80px` to `120px` on left and right borders.
  - Vertical padding: `64px` to `80px` on top and bottom borders.
  - Safe interactive content box: `1680px × 920px`.
- **Responsive Fit Formulation:**
  When rendering on web viewports that differ from 1920×1080, use CSS scale transforms anchored at top-left:
  ```css
  .deck-viewport {
    position: relative;
    width: 100vw;
    height: 100vh;
    overflow: hidden;
    display: flex;
    align-items: center;
    justify-content: center;
    background: var(--bg-deck);
  }
  .slide-stage {
    width: 1920px;
    height: 1080px;
    transform-origin: center center;
    transform: scale(var(--deck-scale, 1));
    aspect-ratio: 16 / 9;
    box-sizing: border-box;
  }
  ```
  The JavaScript scale calculator:
  ```javascript
  function updateDeckScale() {
    const scaleX = window.innerWidth / 1920;
    const scaleY = window.innerHeight / 1080;
    const scale = Math.min(scaleX, scaleY);
    document.documentElement.style.setProperty('--deck-scale', String(scale));
  }
  window.addEventListener('resize', updateDeckScale);
  ```

## 2. Typography & Hierarchy System

Decks fail when text is either too small to read from across a conference room or so long that it overflows the card boundary.

### Type Scale Rules
| Role | Recommended Size | Weight | Tracking / Letter Spacing | Case |
|---|---|---|---|---|
| **Cover Title** | `72px – 96px` | Bold (700) | `-0.025em` | Title Case |
| **Section Heading** | `44px – 56px` | SemiBold (600) | `-0.015em` | Sentence / Title Case |
| **Card / Slide Title** | `32px – 40px` | SemiBold (600) | `-0.01em` | Sentence Case |
| **Key Metric Number** | `64px – 88px` | Bold / Black (800) | `-0.02em` | Tabular Numerals |
| **Metric Label** | `14px – 16px` | Medium (500) | `+0.04em` | All-Caps / Telemetry |
| **Body Paragraph** | `20px – 24px` | Regular (400) | `normal` | Sentence Case |
| **Footnote / Caption** | `13px – 15px` | Regular (400) | `+0.02em` | Sentence Case |

### Display & Body Type Pairings
- **Technical & Architecture:** Space Grotesk (Headings) + Inter / IBM Plex Sans (Body) + JetBrains Mono (Code/Telemetry).
- **Editorial & Executive:** Newsreader / Archivo (Headings) + Inter (Body).
- **High-Impact Growth:** Anton (Key Numbers) + Space Grotesk (Titles) + Inter (Body).

## 3. High-Fidelity PDF Export via Chrome CDP

Standard browser print dialogs inject unwanted headers, footers, margins, and incorrect orientation. Chrome DevTools Protocol (`Page.printToPDF`) enables byte-exact, vector-sharp PDF generation.

### CDP Parameters:
```json
{
  "landscape": true,
  "printBackground": true,
  "preferCSSPageSize": true,
  "paperWidth": 16.0,
  "paperHeight": 9.0,
  "marginTop": 0,
  "marginBottom": 0,
  "marginLeft": 0,
  "marginRight": 0,
  "displayHeaderFooter": false,
  "scale": 1.0
}
```

### Critical CSS for Flawless PDF Export:
```css
@page {
  size: 16in 9in;
  margin: 0;
}

@media print {
  *, *::before, *::after {
    -webkit-print-color-adjust: exact !important;
    print-color-adjust: exact !important;
    box-shadow: none !important;
  }

  html, body {
    width: 1920px !important;
    height: 1080px !important;
    margin: 0 !important;
    padding: 0 !important;
    background: transparent !important;
  }

  /* Force exact page breaks between slide sections */
  .slide {
    page-break-before: always;
    page-break-after: always;
    break-before: page;
    break-after: page;
    width: 1920px !important;
    height: 1080px !important;
    max-width: 1920px !important;
    max-height: 1080px !important;
    overflow: hidden !important;
  }

  /* Hide presenter UI toolbars, thumbnails, and edit consoles */
  #deck-topbar,
  #slide-rail,
  #preview-panel,
  .no-print {
    display: none !important;
  }
}
```

## 4. Editable PowerPoint (`.pptx`) Reconstruction

Unlike tools that convert slides into blurry full-slide raster screenshots, `slidedeck-gen` leverages node-by-node AST reconstruction:
1. **Container Boxes & Cards:** Exported as native PowerPoint shape objects (`pptx.shapes.RECTANGLE`) with matching border colors, border widths, and solid background fills.
2. **Text Nodes:** Preserved as native editable text boxes (`slide.addText`) with matching font face, font size (in points), font weight, color (Hex), alignment, and line spacing.
3. **Images:** Exported as discrete image objects with natural pixel dimensions and preserved aspect ratios.
4. **Tables:** Rebuilt as native editable PowerPoint table structures.

## 5. Visual QA & Verification Checklist

Before delivering any presentation artifact:
- [ ] **Viewport Fit:** Ensure all elements fit comfortably within the 16:9 boundary without vertical scrollbars.
- [ ] **No Text Truncation:** Ensure titles and descriptions do not get cut off (`...`) or overlap adjacent cards.
- [ ] **Contrast Check:** Verify all text satisfies OKLCH `|L_text - L_bg| >= 0.50`.
- [ ] **Metric Alignment:** Numbers and unit symbols must sit on the same baseline.
- [ ] **Media Resolution:** Images must be sharp at 1920×1080 (minimum 1200px wide for hero images).
